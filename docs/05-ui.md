# 5. The UI

Everything visible comes from an `add*` method. Each takes an options object with an `id` (unique within your extension; SOUP prefixes it with your extension id) and an optional `order` (lower first, ties by id), and returns a handle with `remove()`.

## Mounting: plain DOM or React

Where SOUP wants a view (a tab, a panel, a header item) you give it either `mount` or `component`:

```tsx
import { useState } from "react";
import { Plugin } from "soup";

function Counter() {
  const [n, setN] = useState(0);
  return <button onClick={() => setN(n + 1)}>clicked {n} times</button>;
}

export default class Views extends Plugin {
  async onload() {
    // Plain DOM (or any framework you bundle yourself): fill the element, return a cleanup if you need one.
    this.addTab({
      id: "plain",
      label: "Plain",
      mount: (el) => {
        el.textContent = "Hello";
        return () => this.app.log.debug("tab hidden");
      },
    });
    // A React component. It runs on SOUP's own React, so hooks work and nothing is bundled twice.
    this.addTab({ id: "react", label: "React", component: Counter });
  }
}
```

(That block is `.tsx`; the template's `src/main.ts` is `.ts`. Rename the file to `main.tsx` and point `vite.config.ts` `lib.entry` at it to use JSX.)

A throw inside `mount` is caught and shown in place of the view.

## Where things go

### Tabs and panels

```ts snippet
plugin.addTab({ id: "main", label: "My tab", icon: "Sparkles", order: 300, keepMounted: true, mount: (el) => void (el.textContent = "tab") });
plugin.addHeaderItem({ id: "badge", mount: (el) => void (el.textContent = "3 new") });
plugin.addActivityBar({ id: "strip", mount: (el) => void (el.textContent = "A strip under the navigation") });
plugin.addMatchesSidebarPanel({ id: "side", title: "My panel", mount: (el) => void (el.textContent = "in the match history sidebar") });
plugin.addViewer3dPanel({ id: "viewer", title: "My 3D panel", mount: (el) => void (el.textContent = "in the 3D viewer") });
```

`icon` is the name of a [lucide](https://lucide.dev) icon from the list at the end of this page; the default is a puzzle piece. `keepMounted` keeps a tab's view alive while another tab is open (otherwise it is unmounted and mounted again).

### The Library

```ts snippet
plugin.addLibraryReplayAction({
  id: "open-notes",
  label: "Notes",
  slot: "chip", // "chip" (small), "primary" or "secondary"
  when: (replay) => replay.hasJson, // optional: show only when true
  run: async (replay) => {
    app.log.info(`notes for ${replay.id}`);
  },
});
plugin.addLibraryReplayBadge({ id: "flag", render: (replay) => (replay.pinned ? "PINNED" : null) });
plugin.addLibraryFolderAction({ id: "export", label: "Export", run: async (folder) => app.log.info(folder.name) });
plugin.addLibraryToolbarAction({ id: "refresh", label: "Refresh", run: () => app.log.info("toolbar") });
plugin.addMatchRowAction({ id: "open", label: "Open", run: (matchId) => app.log.info(matchId) });
```

`LibraryReplay` and `LibraryFolder` are in `types/soup.d.ts`.

- A **badge** is a small chip next to the replay's name on its tile. `render` returns the text, or `null` for no chip. A badge usually shows your own data, so keep what `addLibraryReplayBadge` returns and call its `refresh()` whenever that data changes: `const badge = plugin.addLibraryReplayBadge({...}); ... badge.refresh();`.
- An **action** with `slot: "chip"` is a small button beside the Replay and Match chips; `"primary"` and `"secondary"` are the big buttons.
- A **match row action** is a button on each row of the Matches tab (the match history, which needs the Riot Client). It gets the match id; for more, call `app.matches.details(matchId)`.
- A **toolbar action** is an entry of the Library's Import menu.

[`examples/scrim-notes`](../examples/scrim-notes/src/main.tsx) uses all of these.

### Settings

Give your extension its own settings page with `SettingTab` and `Setting`, shaped like Obsidian's. Your settings are not mixed
into SOUP's: your row in **Settings > Extensions** gets a cog, and the cog opens your page in its own window. The page says which
profile it saves for. Your own UI can open it too, with `this.openSettings()` (a "Settings" button in your tab).

```ts
import { Plugin, Setting, SettingTab } from "soup";

interface Data {
  shout: boolean;
  colour: string;
  volume: number;
  mode: string;
}
const DEFAULTS: Data = { shout: false, colour: "", volume: 50, mode: "a" };

class MySettings extends SettingTab {
  constructor(
    app: unknown,
    private plugin: Settings,
  ) {
    super(app);
    this.name = "My Extension";
  }

  // SOUP empties the page and calls display() every time it opens.
  display() {
    const el = this.containerEl;
    const p = this.plugin;

    new Setting(el).setName("Look").setHeading();
    new Setting(el)
      .setName("Shout")
      .setDesc("Saved for the active profile.")
      .addToggle((t) => t.setValue(p.data.shout).onChange((v) => p.save({ shout: v })));
    new Setting(el)
      .setName("Colour")
      .setDesc(p.data.colour ? "Your colour." : "The theme's colour.")
      .addColorPicker((c) => c.setValue(p.data.colour || "#4ec98a").onChange((v) => p.save({ colour: v })))
      .addExtraButton((b) =>
        b
          .setIcon("Reset")
          .setTooltip("Use the theme's colour")
          .setDisabled(!p.data.colour)
          .onClick(async () => {
            await p.save({ colour: "" });
            this.redraw(); // empty the page and call display() again
          }),
      );

    new Setting(el).setName("Sound").setHeading();
    const volume = new Setting(el).setName("Volume").addSlider((s) => s.setLimits(0, 100, 5).setValue(p.data.volume).onChange((v) => p.save({ volume: v })));
    volume.setVisible(p.data.shout); // only matters when Shout is on
    new Setting(el).setName("Mode").addDropdown((d) => d.addOptions({ a: "Alpha", b: "Beta" }).setValue(p.data.mode).onChange((v) => p.save({ mode: v })));
    new Setting(el).setName("Start over").addButton((b) => b.setButtonText("Reset everything").setWarning().onClick(() => void p.save(DEFAULTS).then(() => this.redraw())));
  }

  hide() {
    // Clean up anything display() started (a subscription, a timer).
  }
}

export default class Settings extends Plugin {
  data: Data = { ...DEFAULTS };

  async onload() {
    this.data = { ...DEFAULTS, ...(await this.loadData<Partial<Data>>()) };
    this.addSettingTab(new MySettings(this.app, this));
  }

  async save(patch: Partial<Data>) {
    this.data = { ...this.data, ...patch };
    await this.saveData(this.data);
  }
}
```

What a `Setting` row can hold:

| Call | What it adds |
|---|---|
| `setName`, `setDesc` | The row's name and the grey line under it (text, or a `DocumentFragment` you built) |
| `setHeading()` | Makes the row a heading that starts a group |
| `addToggle`, `addText`, `addTextArea`, `addDropdown`, `addSlider`, `addColorPicker` | A control. Each has `setValue`, `getValue` and `onChange` |
| `addButton` | A button: `setButtonText`, `setCta()` (green), `setWarning()` (quiet), `onClick` |
| `addExtraButton` | A small square button beside the control (a "Reset"): `setIcon(text)`, `setTooltip`, `onClick` |
| `setDisabled(true)`, `setVisible(false)` | Grey the row out, or hide it, while it does not apply |
| `setClass("x")` | A class your `styles.css` can style |

Give an input a name for screen readers and tests: `t.inputEl.setAttribute("aria-label", "Folder template")`. Every example has a
settings page: [`scrim-notes`](../examples/scrim-notes/src/main.tsx) (a dropdown, a switch, a confirm),
[`heatmap`](../examples/heatmap/src/settings.ts) (headings, colour pickers with Reset, `redraw`) and
[`auto-organizer`](../examples/auto-organizer/src/settings.ts) (text fields with a live example under them, a folder picker).

### Commands

```ts snippet
plugin.addCommand({ id: "sync", name: "Sync now", hotkey: "Ctrl+Alt+S", callback: async () => app.log.info("syncing") });
```

Every command is listed in the command palette (Ctrl+K), with the extension's name. A `hotkey` is optional and needs Ctrl or Alt (so typing is never hijacked); Ctrl+K belongs to the palette.

### Status text

`plugin.addStatusText("Synced 2 min ago")` puts a line of text on your extension's row in Settings > Extensions. Call it again to change it.

## Notices, dialogs and windows

```ts snippet
import { Modal, Notice } from "soup";

new Notice("Saved"); // a toast
new Notice("Could not save", 6000, "error"); // `tone`: "info" (the default), "success" or "error"; the second argument is how long it stays (ms)

const ok = await app.ui.confirm({ title: "Delete it?", message: "This cannot be undone.", confirmLabel: "Delete", destructive: true });

class Hello extends Modal {
  onOpen() {
    this.setTitle("Hello");
    this.contentEl.textContent = "A dialog you build yourself.";
  }
}
new Hello().open();

app.ui.navigate("my-extension.main"); // switch to a tab: "<extension id>.<tab id>"
```

For a whole separate window see [guide 12](12-windows.md).

## Looking like SOUP

SOUP is dark with square corners, 3px black borders and hard shadows, one accent colour, and plain ASCII text. Match that and your extension looks like part of SOUP.

- The theme is a set of CSS variables on `<html>` (`--forest-900`, `--forest-700`, `--forest-300`, `--foreground`, `--warning`, `--destructive`...). `app.ui.theme.tokens()` returns the current values and `app.ui.theme.onChange(cb)` tells you when the person changes the palette. In CSS: `background: hsl(var(--forest-900));`.
- `app.ui.react.kit` has SOUP's own `Button`, `Switch`, `Progress`, `StatusPill`, `EmptyState`, `ErrorCard` and `SettingsSection` components for React views. Their props can change between SOUP versions, so they are typed loosely; check them in SOUP after each update, or style your own.
- SOUP's CSS class names (the Tailwind classes it uses) are **not** API. Do not rely on them.
- Keep text short and plain; do not use emoji.
